## **1. Opening: The question we should be asking (45 seconds)**

- AI coding assistants have fundamentally changed software development.
- Engineers can now generate code, debug errors, write tests, and build prototypes faster than ever.
- But there's an important distinction between being able to automate something and whether we should.
- Introduce the central question: Should engineers be using AI for everything?

## **2. The case for AI: Why we should embrace it (1 minute)**

Highlight three advantages:

- **Speed:** Reduce time spent on repetitive implementation and boilerplate.
- **Leverage:** One engineer can accomplish work that previously required significantly more time or resources.
- **Accessibility:** Engineers can explore unfamiliar frameworks, understand complex codebases, and experiment faster.

Key argument: AI lowers the cost of experimentation. That is an enormous competitive advantage.

## **3. The danger: When productivity becomes dependency (1 minute)**

This is where you introduce some nuance.

- Engineers might accept code they don't fully understand.
- AI-generated solutions can introduce subtle bugs, security vulnerabilities, and technical debt.
- Over-reliance can weaken debugging skills and independent problem-solving.
- Faster code generation doesn't necessarily mean faster delivery if reviewing, testing, and maintaining that code becomes harder.

**The distinction:** Generating code is easy. Owning the consequences of that code is engineering.

## **4. The middle ground: AI as a copilot, not an autopilot (1 minute)**

Suggest a practical framework:

| Use AI for            | Keep human ownership of    |
| --------------------- | -------------------------- |
| Boilerplate code      | Architecture               |
| Writing initial tests | Test quality and coverage  |
| Debugging suggestions | Root-cause analysis        |
| Documentation         | Technical accuracy         |
| Prototyping           | Production readiness       |
| Code reviews          | Final engineering judgment |

The objective isn't to write every line ourselves. It's to understand, validate, and take responsibility for what ships.

## **5. Closing: The engineers who win (45 seconds)**

- AI won't necessarily replace good engineers.
- But engineers who know how to use AI effectively may outperform those who don't.
- The next generation of great engineers won't be measured by how much code they write.
- They'll be measured by the quality of the problems they solve.
